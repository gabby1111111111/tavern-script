# 杠杠の生图机 V0.4.0

一个运行在 SillyTavern / Tavern Helper 中的轻量异步生图脚本。正文 AI 按当前画图预设输出
`<pic prompt="...">`，脚本在正文完成后异步生图；失败只跳过图片，不阻塞聊天。

当前稳定版本为 v0.4.0，公开安装请使用固定标签 `杠杠の生图机-v0.4.0`。

## 安装

前置条件是已安装 SillyTavern 与 Tavern Helper，并且 Tavern Helper 可以加载后台脚本。

新建一个 Tavern Helper 后台脚本，填入下面的固定版本导入语句：

```ts
import 'https://testingcf.jsdelivr.net/gh/gabby1111111111/tavern-script@杠杠の生图机-v0.4.0/dist/杠杠の生图机/index.js';
```

加载后，在扩展设置中应看到标题为“杠杠の生图机 V0.4.0”的设置抽屉。也可以从对应 GitHub Release 下载 `index.js`
后，按 Tavern Helper 的脚本导入方式加载。

## 用户怎么使用

1. 在“画图预设”中选择或新建预设，填写要发给正文 AI 的指令。
2. 在“出图预设”中用 `{{xx}}` 接入正文 AI 解析出的图片提示词。需要连续剧情时，可在画图预设或出图预设中使用
   `{{xx_pic}}`，并在出图预设中分别开启头像参考和上一镜头图参考；`{{reference_sources}}` 可显示本次实际参考图编号。
3. 在“最近生成”中设置本页保留数量（默认 10 张，可设 1–50 张），并按需删除图片或保存到角色图库。
4. 选择展现方式：
   - `插入正文`：图片生成后放在 `<pic>` 对应段落附近。
   - `礼物异步`：不插入正文，只进入“最近生成”列表，同一楼最多提示一次已送达。
   - 开启“Swipe 新回答也生图”后，原本符合楼层频率且确实生成了新的 Swipe 回复时也会请求图片；切换已有 Swipe 不会请求。关闭后不为新 Swipe 请求图片。
5. 设置“隔几楼”：`0` 表示每个新正常 AI 回复都尝试；`1` 表示第 1 楼尝试、跳过 1 楼、再尝试；依此类推。
6. 在“API”中配置服务地址、模型、API
   Key、尺寸、质量、单次生成数量、超时和额外 JSON。质量支持低、中、高、自动；单次生成数量支持 1–4 张，默认 1 张。
7. 开启连续剧情图后，同一“画图预设＋出图预设”组合会沿用前面楼层当前显示的有效图片及其镜头文字；切换预设会开始另一条连续线。没有有效上一张图时按首图生成。

脚本只统计本次页面运行期间的新 `normal`
AI 回复。重新生成、Swipe、quiet、impersonate、加载历史等不会增加 normal 楼层计数；新 Swipe 是否请求图片由“Swipe 新回答也生图”开关控制，且不会推进楼层计数。切换聊天后从头计数。当前版本暂不在群聊中生图。

## 连续剧情配图

添加并选中“连续剧情”画图与出图示例预设，按需开启“上一镜头图片参考”。头像参考可同时开启。

来源必须属于同一聊天、同一画图和出图预设组合，并是之前楼层当前有效 Swipe 的选中图片。正文开始生成时锁定来源；上一图尚未完成时不会等待，也不会在它完成后回填正在生成的请求。没有合适来源时，上一镜头文字和图片引用为空。

`{{xx}}` 是当前镜头描述，`{{xx_pic}}` 是上一镜头文字，`{{reference_sources}}`
是本次实际可用参考图的编号。已选来源的参考图片读取失败时会跳过，不自动重试。

## 图片与保存

- 每个符合频率的楼层最多处理两条有效 `<pic>`。
- 生成图片默认只保存在当前页面 JavaScript 内存中，默认最多保留 10 张；用户可在“最近生成”中调整为 1–50 张。
- 刷新、脚本重载、卸载或切换聊天后，内存图片会消失，不回扫历史。
- 只有用户明确点击“保存到角色图库”时才调用 SillyTavern `/api/images/upload`；图片列表不承担其他持久化操作。
- 图库保存失败时，页面内存中的原图仍保留，可以再次点击。
- 图片、Base64 和图片地址不会写入 Tavern Helper 脚本变量、聊天变量、消息变量、`localStorage` 或 IndexedDB。

API Key 会以明文保存在 Tavern Helper 脚本变量中。请使用权限受限、可撤销的 Key，不要分享含设置的导出内容。

## v0.2 升级

- 多 API 档案、Key、模型、尺寸、超时和额外 JSON 会保留。
- 旧随文提示词会合并为默认画图预设。
- 旧礼物提示词会合并为“v0.2 礼物 CG 兼容预设”，不会静默丢失文字配置。
- 旧的三张手工参考图只存在于页面内存，不迁移；v0.3 改为读取当前 User 与角色头像。
- 旧手动礼物任务、3/5 楼调度和预测槽已移除。

## API 请求

运行时统一调用：

```ts
requestImages(profile, { prompt, referenceImages? }, signal)
```

无参考图时发送普通 generation 请求；有参考图时按端点/档案兼容 multipart edit、Chat 多模态或 JSON 参考图。`quality` 和
`n` 随 API 档案发送；每个任务只请求一次，不自动重试。

同一个 `<pic>`
一次返回多张图片时，正文中用图片两侧的左、右按钮查看同批候选图。点击“修改提示词并生成”会直接展开本次实际发送的最终提示词，可编辑或一键清空；文本会随当前图片保存在页面内存中，再次打开时保留上次修改。两个参考开关只影响本次重绘，并按当前图片实际记录设置默认值；未选择的参考图不会被读取。确认时使用编辑后的最终文本，只请求 1 张，并把结果追加到该候选图的版本历史中。

“区域重绘”默认开启“无需画笔”，只发送当前图和修改提示词；关闭该选项后才使用原图加洋红标记图的区域约束。两种操作都只请求 1 张，用上、下按钮切换版本；删除只删除当前版本。

候选图的左、右箭头位于图片两侧中央，没有上一张或下一张时隐藏对应箭头；右下角只显示当前重绘版本页码、上下版本按钮和图片操作按钮，不显示独立的候选页码。重绘期间仅对应操作按钮显示加载状态和 spinner，原图和其他操作保持可用。切换 Swipe 后，已提交的自动生图和手动重绘继续执行，结果保留在原 Swipe；切回后可以查看生成进度或完成的图片，不会覆盖当前 Swipe 的图片。关闭总开关或删除对应目标时会取消相关任务。

## 候选与重绘版本清理

- 图片右下角的“固定”表示满意当前版本：立即清理同一楼、同一 Swipe、同一插图位置的其他候选和重绘版本，只保留当前这张。
- 新的一条消息或回复进入下一楼时，自动清理上一楼的图片，不等待下一次配图。每个插图位置跨全部 Swipe 最终只留一张：有手动固定时优先保留最近固定的版本；没有时保留当时聊天界面正显示的版本，作为默认固定版。
- 同一楼不同插图位置分别处理，不影响其他楼层。切换 Swipe、同楼重生成和加载历史不会触发自动清理。
- 清理同时释放正文与“最近生成”中的被淘汰版本；保留下来的图片仍只存在当前页面内存里。
- 删除消息、删除 Swipe 或楼层重排时，图片任务、placement 和当前页面内的固定选择会按消息与 Swipe 身份校正；失效 scope 的迟到结果不会复活或覆盖其他图片。

正文渲染时，Markdown 代码块和行内代码中的 `<pic>` 示例会保留，不会被当作真实生图标记清理。

## 开发与验收

- ESLint：`pnpm exec eslint "src/杠杠の生图机"`
- 相关回归脚本位于仓库根 `tests/`。
- 生产构建：`pnpm build`
- 真实运行时需检查 `window.__storyImageAudit` 的
  `run_id`、`lifecycle`、`injection`、`generation`、`markers`、`tasks`、`gift`、`cache` 和 `last_error`。
- 头像参考、上一镜头图参考、不同 API 请求模式、inline、gift、图库保存都需要在真实 SillyTavern 中单独验收；静态构建不能替代实际 API 和视觉效果。
- 本版代码已覆盖连续图的来源筛选、请求快照、失败降级、编辑器与区域重绘回归；真实 API 的组合兼容性仍取决于用户配置的服务端能力。
