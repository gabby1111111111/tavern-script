# 杠杠の生图机

一个运行在 SillyTavern / Tavern
Helper 中的轻量异步生图脚本：聊天正文先正常出现，图片随后作为随文插图、礼物 CG 或页面内复用内容到达。图片失败不会阻塞正文。

## 它能做什么

- 每条 AI 回复根据正文控制标记生成最多 2 张随文插图。
- 使用“角色 1 + 角色 2 + 姿势”三张参考图生成礼物 CG。
- 礼物 CG 可手动触发，或每 3 / 5 条新 AI 回复自动尝试一次。
- 最近生成最多保留 5 张，可下载、复用到最新 AI 回复、添加一句短配文，并撤回上一次复用。
- 随文插图和礼物 CG 可分别选择 API 配置档案。
- 礼物 CG 成功后显示一次轻量到达提示。

核心原则是快、轻、可拔插：不建立图片数据库，不回扫和恢复历史楼层，不自动反复重试，也不要求用户为了偶发失败停下聊天。

## 安装

前置条件：

- 已安装并启用 SillyTavern。
- 已安装 Tavern Helper，并能加载 Tavern Helper 后台脚本。

请使用脚本专属版本标签中固定的 production bundle，不要直接依赖不断变化的 `main` 分支。新建一个 Tavern
Helper后台脚本，填入下面的固定版本导入语句；加载后在扩展设置中打开“杠杠の生图机”设置抽屉。

```ts
import 'https://testingcf.jsdelivr.net/gh/gabby1111111111/tavern-script@杠杠の生图机-v0.2.0/dist/杠杠の生图机/index.js';
```

也可以从 GitHub Release 下载 `index.js` 后按 Tavern
Helper 的脚本导入方式加载。首次安装或宿主升级后，请实际确认脚本加载成功、设置抽屉出现；不要仅凭构建成功推断运行时已经通过。

## 初次配置

1. 新建或编辑一个 API 配置档案。
2. 填写 API 地址、API Key、模型、尺寸、超时及服务需要的额外 JSON。
3. 分别为随文插图和礼物 CG 指派档案。
4. 根据服务端接口选择请求模式。
5. 如需礼物 CG，分别上传本地图片或填写 URL，准备角色 1、角色 2 和姿势三张参考图。

API Key 会以明文保存在 Tavern Helper 脚本变量中。请使用权限受限、可随时撤销的 Key，不要分享包含这些设置的导出内容。

## 请求模式

| 模式           | 请求形态                                   | 常见用途                   | 注意事项                                 |
| -------------- | ------------------------------------------ | -------------------------- | ---------------------------------------- |
| 自动判断       | 根据端点选择兼容请求                       | 已知官方或常见兼容端点     | 只能判断请求形态，不能保证任意服务商兼容 |
| multipart 编辑 | `multipart/form-data` 发送提示词和多张图片 | `/images/edits` 类端点     | 图片字段名与鉴权要求必须符合服务端协议   |
| Chat 多模态    | 在聊天消息中发送文本与参考图               | `/chat/completions` 类端点 | 模型必须支持图片输入和图片结果           |
| JSON 参考图    | 在 JSON 字段中发送参考图                   | 自定义兼容服务             | 需要手动核对服务要求的字段名             |

官方 OpenAI 多图编辑接口使用重复的 `image[]` multipart 字段和 `Authorization: Bearer ...`；自定义兼容站可能仍要求重复的
`image` 字段或额外鉴权头。脚本的兼容选项只负责构造请求，不替代真实 API 验收。参见
[OpenAI Image generation guide](https://developers.openai.com/api/docs/guides/image-generation)。

## 使用方式

### 随文插图

启用功能并配置随文档案后，脚本会在生成期注入控制协议，扫描正文 AI 的累计输出，在相应段落旁异步生成图片，并在最终消息到达后清理控制标记。每条回复最多处理两张图。

### 礼物 CG

三张参考图都准备好后，可以在设置页手动生成，或选择每 3 /
5 条新 AI 回复自动尝试。自动计数只统计本次页面运行期间首次收到的新 AI 楼层；缺参考图、已有礼物任务或请求失败时，本次直接跳过，不排队、不补跑。

礼物 CG 是后台彩蛋，允许晚于触发它的剧情到达。成功后会进入最近生成并提示一次。

### 最近生成与复用

最近生成只保留当前页面最多 5 张图片。复用会把选中的图放到最新 AI 回复的当前 swipe，并可附带不超过界面限制的短配文；它只修改页面 DOM，不修改聊天正文。撤回只针对上一次复用。

## 数据与隐私

| 数据                           | 保存位置                       | 何时清除                             | 是否发给图片服务               |
| ------------------------------ | ------------------------------ | ------------------------------------ | ------------------------------ |
| 生成图片、最近生成             | 当前页面 JavaScript 内存       | 刷新、脚本重载、卸载或切换聊天       | 图片服务返回的数据             |
| 三张礼物参考图                 | 当前页面 JavaScript 内存       | 清空、刷新、脚本重载、卸载或切换聊天 | 生成礼物 CG 时会发送           |
| 随文任务与复用位置             | 当前页面 JavaScript 内存 / DOM | 生命周期失效、刷新、卸载或切换聊天   | placement 不发送               |
| API 档案、提示词、API Key      | Tavern Helper 脚本变量         | 用户修改或清除设置                   | 请求时发送给所选服务           |
| 礼物的有限角色资料与最近上下文 | 不作为图片历史持久化           | 单次任务结束                         | 会发送给用户配置的礼物图片服务 |

礼物任务最多会使用最近 12 条聊天消息，并与三张参考图一起发送给所选服务。请先确认该服务的隐私政策和数据用途。

脚本不会把生成图片、Base64、图片地址或图片任务写入正文、消息变量、聊天变量、 `localStorage`、IndexedDB 或
`image2store://`。审计和日志也不得记录 Key、Base64、图片地址、完整响应、完整聊天或大段提示词。

## 已知限制

- 刷新、重载或切换聊天后，历史楼层图片不会恢复；这是有意的轻量设计。
- 每个图片任务只请求一次。失败后不会自动换源或重试；随文图可修正配置后重新生成/滑动回复，礼物 CG 可手动再点一次。
- 远程参考图必须允许浏览器读取，可能受到 CORS、鉴权和防盗链影响；遇到问题优先改用本地上传验证。
- 本地参考图会在当前页面内缩放，最长边不超过 2048px；URL 只接受 `http://` 或 `https://`。
- 每条回复最多 2 个随文标记；最近生成最多 5 张；同一时间只运行 1 个礼物任务。
- 自动礼物不会回扫历史，切换聊天或删除消息后会重新计数。
- 三种 API 模式只是请求形态，不保证所有 OpenAI 兼容站都遵循同一套图生图协议。
- `prediction-slot.ts` 目前是内部基础设施，预测生图尚未作为公开功能接入。

## 常见问题

### 刷新后图片为什么消失？

图片只在当前页面内存中存在，没有写进聊天记录。需要长期保存的图片请手动下载。

### 文本已经出来，图片失败了怎么办？

正文不受影响。先检查所选档案、端点、模型和请求模式；确认后重新生成相应回复，或手动再生成一次礼物 CG。

### 为什么自动礼物没触发？

先确认三张参考图齐全、自动频率已开启、当前没有礼物任务，并且这些楼层确实是本运行期新收到的 AI 回复。具体跳过原因可查看审计对象的
`gift` 区域。

### 为什么本地参考图能用，图床 URL 不行？

通常先查图床的 CORS、防盗链、鉴权或重定向。浏览器必须能直接读取图片 URL，API 本身能访问该 URL并不能证明浏览器也能读取。

### 自定义站能图生图，官方端点却失败？

先核对 multipart 图片字段名和鉴权头，再看模型与端点；不要先改提示词。排障路线见 [代码线路图](docs/ARCHITECTURE.md)。

## 开发与验收

- 局部静态检查：`pnpm exec eslint "src/杠杠の生图机"`
- 目标测试位于仓库根 `tests/`，是逐文件执行的 TypeScript 回归脚本，不是 Vitest suite。先用
  `rg -l "杠杠の生图机" tests -g "*.test.ts"` 列出完整集合；PowerShell 中按下面的方式逐个运行：

  ```powershell
  $env:TS_NODE_COMPILER_OPTIONS='{"module":"CommonJS","moduleResolution":"Node","ignoreDeprecations":"6.0"}'
  node --require ts-node/register/transpile-only tests/gift-image.test.ts
  ```

- 生产构建：`pnpm build`；发布前必须确认目标 `dist` 是生产 bundle，而不是 `pnpm watch` 生成的开发 bundle。
- 真实运行时：在 SillyTavern 中检查 `window.__storyImageAudit` 的
  `run_id`、`lifecycle`、`injection`、`generation`、`markers`、`tasks`、`gift`、`cache` 和 `last_error`。
- 图生图、本地/URL 参考图及实际使用的不同 API 模式必须分别实测；静态测试不能替代。
