## 2026-09-09：产品讨论记录与后续方向

当前正式发布基线为 `杠杠の生图机-v0.4.0`。本节保留发布后的讨论脉络；异步工作流和配图资格现已纳入上方 v0.4.2 授权范围，保存能力仍为暂缓候选。下文较早的版本阶段、Git 锚点和非目标是历史背景；有冲突时以上方 v0.4.2 范围为准。

### v0.4 后续：可选保留当前图片，支持边聊边修

使用动机：单次生图或重绘常需两三分钟，连续剧情图经过多次选择与修改后已成为这份聊天的一部分。用户希望保留这些成果，也希望修图不阻碍继续聊天。异步部分先进入 v0.4.2，持久化的版本和方案未定。

已确认的需求方向：

- 图片保存可选，并与具体角色的具体聊天关联；同一浏览器刷新、关闭后重开或电脑重启后，再打开该聊天仍能看到保留的图片。当前不要求跨浏览器同步。
- 只长期保留聊天正文中当前留下的图片，不保存所有候选和重绘历史。“当前展示”包括需要向上滚动才能看到的图，不局限于屏幕可视区域；每个插图位置以当前留下的底图为准，不能把浏览候选误当作采用。
- 增加页面悬浮球，作为生图机的另一个入口；打开后集中查看当前聊天已有的图、生成/重绘状态，并可查看和重绘，不必向上翻找聊天楼层。
- 每张图显示对应镜头文字 `{{xx}}`、楼层号，并保留回到所属聊天记录楼层的入口；正文与面板应对应同一张图。
- 用户可以继续聊天，同时查看和修改此前图片；后续剧情生图前，由用户把控希望使用的上一张图。不能默认用户必须在当前楼修到满意才往下聊。
- 图片与原楼层的关联首先服务于恢复、修图和回看原文，不按尚未确定的视频输入协议提前设计。

#### 本轮续谈已确认：底图、候选与确认

- “继续开启新的聊天”在这里指同一份聊天继续发消息、进入下一楼，不是新建聊天文件。
- 继续往下聊时，上一楼当前选中的图至少是用户决定留下继续修的底图，不要求已经满意；该插图位置此前未选中的候选和旧版本可以清理。
- 用户可在悬浮面板持续重绘旧镜头，同时继续聊天。此后产生的待选重绘版本在当前页面内可比较、查看、继续修改，不能被后续聊天推进反复清掉。
- 新结果不自动采用；仅查看、放大或生成完成都不等于确认。用户明确选中/确认后，才替换留下的底图，并成为后续剧情可用的已确认参考。
- 保存方向的讨论偏好（暂缓实现）：保存和确认分开；若未来保存未确认底图，恢复后仍应未确认，不能自动进入参考来源。
- **待选版本刷新后直接丢弃**。未来保存范围倾向只保留各镜头留下的底图及确认状态；v0.4.2 仍不保存任何底图或确认状态，刷新后都清空。
- 确认某一版本后，只保留该镜头被确认的图，清理该镜头的其他候选和版本；确认 C 不能顺带删除仍在修的 B。

#### 本轮续谈已确认：异步参考选择与提醒

- 不强制拦截正文，不要求用户在弹窗里操作后才能聊天。放弃先前讨论的“暂停正文请求等待选图”方案。
- 沿用正文生成开始时判断配图资格、确定本轮参考来源的时机；正文完成并解析到有效标记后才请求生图。提醒只告知，不阻塞、不要求立即选图。
- 在当前聊天、当前预设组合的有效剧情顺序内，优先使用距离本轮最近的已确认镜头；不是按重绘完成时间或最后点击确认的时间选择。
- 例如 A 已确认、B 未确认，此时生成 C：使用 A，提醒 B 尚未确认、本次沿用 A；没有已确认镜头库存时，不附上一剧情图并提醒，头像仍按原开关处理。
- 正文的上一镜头文字和生图的上一剧情参考必须取自同一来源；无来源时，受支持位置的 `{{xx_pic}}` 按现有空值规则展开为文字 `null`。`{{reference_sources}}` 仍描述实际附带来源，头像可用时不会因此变空。
- B 和 C 可以同时待确认，互不覆盖。B、C 都未确认时下一轮用 A；仅 B 确认时可用 B；C 确认后即优先用 C，之后确认较早的 B 不抢占 C。
- C 使用 A 发出的请求保持该来源记录；之后确认 B 不改变 C，也不自动重跑 C。由用户决定是否重绘以调整视觉连贯性。
- 用户随时可“放弃整个镜头 B”：清理 B 底图、候选及相关在途任务，迟到结果不得复活；后续按当前剧情顺序使用最近有效的已确认镜头；若已有较后的已确认 C，仍优先 C，没有有效库存则走无上一剧情图路径。
- “删除单个候选”与“放弃整个镜头”是不同操作；本轮自动回退使用 A 不等于自动删除 B。

#### 本轮续谈已确认：删除、换回答与配图资格

- 删楼就删除该楼图片和任务。重点照顾修改最近一两楼、重新生成最新回复的日常工作流；较早楼层删除仍需正确清理和关联校正，不另建复杂历史编辑流程。
- 图片跟随具体消息及 Swipe，而不只看数字楼层号：Swipe 保留旧回答时，旧图随旧回答保留；删楼后同编号的新回答不能继承旧图。直接重新生成移除旧回答时，也清理对应图片和任务。
- **配图资格和图片生命周期分开。** 例如第 10 楼已经该配图，无论 Swipe 新回答、删掉该楼后再生成，还是直接重新生成，该剧情位置的配图资格都不丢失，三种换回答操作不额外推进配图间隔。
- **保留“Swipe 新回答也生图”开关。** 有资格的楼层进行新 Swipe 时，开关开启才实际尝试生图；关闭则跳过本次 Swipe 生图，但不清除该楼资格。先前建议取消该开关的说法已被用户否决。
- 删楼再生成和直接重新生成使用原配图资格，不受 Swipe 开关影响。所有自动配图仍受生图总开关控制。
- 切换查看已有 Swipe 不重复请求生图。获得资格表示该轮应要求正文输出生图标记，不承诺正文一定输出有效标记或图片 API 一定成功。
- 改造前的缺口：`regenerate` 被自动配图门控排除，删楼未回退累计计数，Swipe 依赖页面内消息资格记录。三种入口的统一属于正在实施的 v0.4.2，完成状态以整体验收为准。

存储阶段暂缓，之后再讨论：

- 存储介质、启用范围与默认值、容量与清理方式、恢复流程；本次没有选定 IndexedDB、服务器文件或其他技术方案，也没有授权把图片写进聊天正文或变量。
- 多个 Swipe 下各底图的持久化范围，以及刷新后配图计数和位置资格怎样恢复；不能仅凭同一个数字楼层号认领历史图片或资格。
- 删除聊天文件、关闭保存开关或关闭生图总开关时，已保存内容及在途任务的具体处理。
- 保存内容与确认/选择交互怎样衔接；不默认刷新后自动续跑 API 请求。

悬浮面板布局、交互和在途任务收尾按 v0.4.2 执行简报实施和验收。当前代码仍采用页面内存生命周期，可选保存尚未设计，不改写现行存储约束。

## 历史方案：v0.4 按预设组合延续的连续故事配图

以下保留 v0.4.0 设计背景；其中“当前显示即参考”“无须确认”和空字符串等旧语义，已分别由 v0.4.2 的已确认来源规则和字面文字 `null` 规则替代，不用作本轮验收要求。

> 计划更新：2026-09-08（中国标准时间 UTC+8）。以下为已确认的产品方案；Gabby 已在本次会话授权开始开发，但不代表各项功能已经通过验收或发布。
> 实施按“来源选择 → 快照与生命周期 → 文字/图片引用 → 设置示例 → 整合验收”的顺序推进，真实环境测试安排在纯代码验收之后。
> 本节替代此前“全聊天上一张图”和“合并重绘描述”的旧方案。

### 定位与目标

v0.3 解决“这一楼的配图符合这一楼剧情”；v0.4 解决“聊了十几楼，同一系列的图片连起来像同一个故事”。

主要面向 GPT Image 这类支持自然语言和参考图的 LLM 生图 API。基础用户配置好一个生图 API 和头像，正常聊天即可延续人物、服装、场景和画风，同时随剧情改变动作与画面。不要求用户管理衣服库、角色资产或每楼手选参考图。

### Step 1：按预设组合建立独立连续线

- 以“画图预设 ID + 出图预设 ID”识别组合，在当前聊天中独立延续。
- 图片属于生成开始时锁定的组合；之后切换预设不改变已有图片的归属。
- 改名或编辑同一个预设仍属于原组合；新建预设形成新组合。
- 例如生成顺序为“剧情 A1 → 心理 B1 → 心理 B2 → 剧情 A2”，A2 自动参考 A1，B1、B2 不影响它。
- 同组合里不同用途的图片也会参与延续；需要独立连续线的风景、心理或抽象图，通过不同组合区分，不额外让 AI 自动分类。
- 当前组合没有有效图片时，按首次生图处理。

验收：

- Codex 验收：目标测试检查组合归属、预设切换及首次生成；结果记录精确命令与文件。
- 运行时审计验收：真实酒馆交替使用 A、B，核对 `window.__storyImageAudit` 中组合与来源身份，确认不串图。
- 人工验收：分组是否符合日常使用习惯。

### Step 2：以聊天界面当前显示图片为准

**向前找到当前组合最近一个有效的正文插图位置，使用该位置当前在聊天界面显示的图片；不是按生成时间取最后一次生成的图。**

- 只在当前聊天、当前楼层之前、当前有效 Swipe 分支中寻找属于该组合的插图。
- 同一楼即使生成了 10 次 Swipe 并多次重绘，用户最后显示第 4 次 Swipe 的中间某个重绘版本，后续就参考此刻显示的这个版本。
- 直接跟随现有界面的 Swipe、横向候选和纵向版本显示状态；不新增参考图挑选器或独立选中状态。
- “当前显示”指聊天界面当前选中的有效图片，不要求图片恰好位于屏幕可视区域。
- 图片被删或所在楼层失效时，重新向前寻找同组合最近一张有效、当前显示的图；找不到就按首次生图处理。
- 同楼多个插图位置按正文顺序选最后一个有效位置，不按 API 返回顺序选择。
- 当前楼生成新的 Swipe 时，仍从前面楼层寻找参考，不使用本楼已放弃的 Swipe 图。
- 礼物图本版不参与连续线。

验收：

- Codex 验收：目标测试覆盖组合过滤、当前显示状态、正文顺序和删除回退。
- 运行时审计验收：真实酒馆多次 Swipe、重绘、切回中间版本、删图和删楼，核对参考身份及失效状态。
- 人工验收：确认“下一张参考的就是聊天界面当前那张图”，不出现最新生成版本抢占参考。

### Step 3：增加文字占位符与独立图片引用

| 占位符 | 含义 | 可用位置 |
| --- | --- | --- |
| `{{xx}}` | 当前楼正文 AI 输出并由 `<pic>` 解析的本次画面提示词 | 出图预设 |
| `{{xx_pic}}` | 当前组合参考图所属镜头的画面提示词 | 画图预设、出图预设 |

- `{{xx_pic}}` 只展开文字，不展开图片 URL、Base64 或二进制，也不自动触发图片引用。
- `{{xx}}` 在正文生成前尚不存在，不扩展到画图预设。
- 出图预设保留 `useAvatarReferences`，新增独立选项 `usePreviousStoryImage`。

| 头像参考 | 上一张图参考 | 实际图片顺序 |
| --- | --- | --- |
| 关闭 | 关闭 | 省略 `referenceImages` |
| 开启 | 关闭 | User 头像 → 角色头像 |
| 关闭 | 开启 | 当前组合参考图 |
| 开启 | 开启 | User 头像 → 角色头像 → 当前组合参考图 |

没有有效参考图时，`{{xx_pic}}` 为空并跳过该图片来源，正文与普通生图继续。不得发送空图片维持编号；来源读取失败时，只发送实际可用图片，来源说明必须与真实编号一致。

画图预设示例：

```text
上一镜头的画面提示词：
{{xx_pic}}

请结合当前剧情判断哪些视觉元素继续保持，哪些已经改变，
并在本次回复中输出新的、完整的 <pic> 画面提示词。
```

出图预设示例：

```text
上一镜头的文字背景：
{{xx_pic}}

当前镜头：
{{xx}}

延续未被当前剧情改变的视觉细节，按当前剧情更新动作与场景。
若提供上一镜头参考图，旧文字与该图的局部细节不一致时，以图为准；
当前剧情明确要求的新变化优先。
```

验收：

- Codex 验收：目标测试检查占位符、空值降级、四种请求组合与来源编号。
- 运行时审计验收：真实正文模型核对注入，真实生图 API 验证四种引用组合；审计记录来源类型、数量和状态。
- 人工验收：预设填写和开关是否易懂。

### Step 4：正文 AI 判断变化，图片保留重绘后的状态

- 头像提供人物身份参考；当前组合参考图提供尚未改变的服装、道具、环境及视觉细节。
- 正文 AI 根据聊天与上一镜头文字判断延续、换装、换场及动作变化，输出本次完整画面描述。
- 不增加独立导演、视觉识别或总结模型调用；不把上一张实际图片作为附件发送给正文 AI。
- **重绘结果直接体现在图片上，图片本身就是最新视觉状态。不维护、合并或整理额外的重绘描述文字记录。**
- 局部重绘后的 `{{xx_pic}}` 沿用该图所属镜头的画面提示词，不追加区域修改历史，不要求文字完整重述每次重绘后的结果。
- 例如白花重绘成红玫瑰，下一次直接发送显示红玫瑰的图，不另存“白花改红玫瑰”的连续性记录。
- 预设明确：旧描述与参考图局部细节冲突时以图为准，当前剧情明确的新变化优先。只有文字引用、未开启图片引用时，不承诺传递重绘后的视觉细节。
- 镜头提示词不能直接保存为递归嵌套了 `{{xx_pic}}` 的完整 API 请求。每次只引用一个镜头的文字，避免十几楼后累积历代提示词；文字长度应有界，具体上限在开发时按真实预设验证。
- 提供可直接使用的“连续剧情”预设示例；不建立额外的候选/重绘参考挑选机制。

验收：

- Codex 验收：检查镜头提示词与图片关联、无历史递归增长、无额外重绘描述存储及额外模型请求。
- 运行时审计验收：真实模型和图片 API 验证连续场景、换装、换场、局部重绘后继续出图；静态检查不替代真实结果。
- 人工验收：人物识别度、环境连贯感、剧情变化是否自然；参考引导不承诺像素级一致。

### Step 5：锁定快照，不阻塞聊天，不持久化连续线

- 正文生成开始时锁定预设组合、参考图及所属镜头提示词。画图预设、出图预设与图片请求使用同一快照。
- 快照应能定位聊天、消息、Swipe、插图位置和当前显示图片身份；使用现有候选/版本身份即可，不创建独立挑选机制。
- 本轮开始后切换图片或预设只影响后续生成，不改变已经启动的请求；源状态失效按生命周期取消或丢弃，不静默换成另一张参考图。
- 同楼多个图片任务共用生成开始时的快照。
- 上一楼图片尚未生成完时，使用同组合已有的有效显示图；没有就首次生图，不等待图片。
- 失败不自动重试、不补跑，不影响正文，也不替换已有有效参考。
- 切聊天、删楼、关闭或卸载等导致任务失效时，取消或丢弃过期结果，释放资源。
- 图片、连续线关联及快照只留在本页 JavaScript 内存；刷新、脚本重载、卸载或切换聊天后清空，不回扫恢复历史。
- 不将图片或连续性任务数据写入正文、聊天/消息变量、脚本设置、localStorage、IndexedDB 或 `image2store://`。预设文字与开关沿用现有设置存储。
- 只有用户明确点击保存到角色图库时才持久化图片；图库保存不等于持久化或恢复连续线。
- 审计沿用 `window.__storyImageAudit` 和 `<杠杠の生图机>`，记录有界的组合、来源身份、快照及失效状态，不记录 Key、图片地址、Base64、完整提示词或聊天。

验收：

- Codex 验收：目标目录 ESLint、相关测试、必要生产构建和限定范围 diff 检查，记录实际命令及结果。
- 运行时审计验收：真实酒馆验证慢请求、失败、生成中切图、删楼、切聊天和资源释放；核对审计与事件证据。
- 人工验收：连续出图的聊天节奏和交互舒适度。

### v0.4 非目标与执行边界

- 不做独立的历史参考图选择器、任意上传、自由排序或无限参考槽。
- 不做衣服库、场景库、角色资产管理等精细控制。
- 不做跨聊天引用、刷新后恢复连续线、礼物图连续线。
- 不做额外文字模型分析、自动重试、预测、持久任务队列或后台补跑。
- 不新增重绘文字历史的维护、总结与合并机制。
- 本计划不修改 v0.3 已发布功能说明或 CHANGELOG，不意味着任何 v0.4 功能已经交付。
- 已完成基于 v0.3.1 的目标 Git 核对并建立文件所有权与 Step N 执行简报；本轮允许功能代码开发，不提交、不发布。

## v0.5：更自由的参考图系统

### 方向

v0.5 从 v0.4 固定的“头像 + 上一张剧情图”扩展到可配置参考来源。候选能力包括：

- 自定义图片或角色图库图片。
- 指定某一张历史剧情图，而不只自动选择上一张。
- 固定场景、服装、姿势或画风参考图。
- 多角色头像和多种人物身份来源。
- 每个来源独立启用、删除、命名与排序。
- 在 API 能力允许时，为来源声明用途或优先级。

### v0.4 应预留的内部边界

v0.4 前端仍只显示两个简单开关，但内部先把来源解析为有类型、有顺序的请求期列表：

```ts
type ResolvedReferenceSource = {
  kind: 'user-avatar' | 'character-avatar' | 'previous-story-image';
  label: string;
  value: string;
};
```

模块②负责解析和排序来源，模块③只接收最终结构：

```ts
{
  prompt: string
  referenceImages?: string[]
}
```

这样 v0.5 可以扩展来源注册、排序和界面，而不推翻 v0.4 的图片 API、任务生命周期与展现模块。

### 尚未决定

- 自定义参考图的来源、选择器和生命周期。
- 是否允许保存参考图配置，以及大图应放在哪里；图片二进制仍禁止进入 `extension_settings`。
- 不同 API 对参考图数量、排序、用途和图生图能力的差异如何向用户展示。
- 自由排序与“图 1 / 图 2”提示词之间怎样保持可靠映射。

以上内容需要在 v0.4 连续剧情图经过真实使用后再定，不提前写死。
