# 杠杠の调音台 v0.3.1

发布日期：2026-10-18

## 修复与改进

- 解决 v0.3.0 已知限制 "Swipe 新回答也出歌" 在部分运行时事件顺序下偶发不触发。
- Swipe 资格管理改为按生图机同样帧设计的 floor ledger（`src/杠杠の调音台/bgm-eligibility.ts`）。
  Swipe 资格读取不再依赖 `MESSAGE_SWIPED` 事件，ledger 通过 `chat[targetMessageId]`
  直接定位原楼层对象，对宿主运行时事件顺序差异天然免疫。
- normal 提交走 ledger `commit` 路径，stale / duplicate settlement 会被显式拒绝。

## 帧设计参考

帧设计参考 `src/杠杠の生图机/generation-eligibility.ts`。两条实现按以下方式解耦：
- 共用 ledger 帧（records WeakMap + bounded current-chat tail + replacement / pending 状态机）
- 调音台不引入生图机的 displayPolicy、regenerate、MessageAdvanceGate 等业务字段
- 调音台专属 `BgmFloorEligibilityLedger<T>` 仅暴露 `'normal' | 'swipe'` 两种入口类型

## 数据流变化（relative to v0.3.0）

```
旧 (v0.3.0)               新 (v0.3.1)
MESSAGE_SWIPED 事件        ← 仅作 audit，日志 debug 看
  ↓
pendingSwipeTarget 全局变量 ← 退化为审计定位，资格门控不再依赖
  ↓
floorDecisions: WeakMap    → floorEligibility: ledger
  (直接 set/get)              (prepare → get → commit 事务化)

旧 swipe 资格路径：
pendingSwipeTarget 或 fallback getLastMessageId()
  → floorDecisions.get(messageRef)
  → undefined 时 silence skip

新 swipe 资格路径：
ledger.prepare({ type: 'swipe', targetMessageId, chat })
  → original = chat[targetMessageId]
  → existing / replacement 命中 → 复用；不命中 → return null
  → return object identity of 原楼层 → still hits records
```

## 失败模式

- ledger.prepare swipe 在没有 inherited record 时返回 null（旧路径会拿到错楼 decision 误触发）；
  行为上仍表现为 "skip"，但语义更准确——这不是"沉默失败"，而是"该楼层确实没有原资格"。
- ledger.commit 在 chat shape mismatch 时返回 false，背景脚本 warn 后不再强制写入 record。

## 升级

- 保留旧 `dist/杠杠の调音台/index.js` 安装路径，原有脚本变量设置可继续使用。
- 更新固定版本导入标签为 `杠杠の调音台-v0.3.1`。
- 无破坏性 API 变更（`BgmMessageIdentityStore` 仍为 bgm-settings.ts 内部 export，未在 API surface 暴露）。
