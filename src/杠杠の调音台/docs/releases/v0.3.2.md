# 杠杠の调音台 v0.3.2

修复“BGM 每次都搜歌失败、播不出歌”的问题。

> **本版本备注：B 站环境音模块为闲置状态、不可用。**
> B 站取播放地址的接口已不再返回音频（搜索仍能返回 BV 号），
> 所以环境音解析不出可播放音频。**BGM 不受影响。**
> 请在“环境音”中关闭该模块，等待上游恢复。

## 问题

v0.3.1 及之前，BGM 的播放地址固定向 JOOX 请求。该接口已停止返回音频地址：
实测 48 首候选（覆盖本脚本内置的 6 个歌单）**全部**返回

```json
{ "url": "", "br": -1, "size": 0 }
```

于是每一轮出歌都在 `歌曲没有可用 URL` 处失败——不是偶发，是必现。

一个容易误解的点：**即使选择了网易云歌单，播放也走 JOOX**。
`bgm-playlist.ts` 只从网易云取曲目名，真正解析播放地址仍在
`searchAndPlayBgm()` 里使用固定音源。所以切换歌单并不能绕过这个问题。

## 修复

音源改为网易云，并抽成单一常量：

```ts
// index.ts
type MusicSource = 'netease' | 'joox' | 'bilibili';
const BGM_TRACKED_MUSIC_SOURCE: MusicSource = 'netease';
```

JOOX 与 B 站仍保留在可选类型中，日后若对方接口恢复，改这一个常量即可，
不需要再改调用点。

同时把日志与审计字段里写死的“JOOX”改为与实际音源一致，
避免下次排查时被旧字样误导。

## 实测结果

对内置 6 个歌单各取前 8 首（共 48 首）跑完整 `搜索 → 取地址` 链路：

| 歌单 | 网易云 | JOOX |
| --- | --- | --- |
| kpop i like | 8/8 | 0/8 |
| 热歌榜 | 8/8 | 0/8 |
| 飙升榜 | 8/8 | 0/8 |
| 新歌榜 | 8/8 | 0/8 |
| 华语金曲榜 | 6/8 | 0/8 |
| 没killed之前的噪音 | 8/8 | 0/8 |
| **合计** | **46/48（96%）** | **0/48（0%）** |

可播样本均为 320kbps、6–12 MB 的完整曲（非试听片段）。
未取到地址的 2 首：《远方 (组曲)/张萌萌》《动地惊天爱恋过/余春娇》。

## 关于音源选择的说明

- 此前“很多歌只有 JOOX 有”的判断基于 JOOX 可用时的情况。当前 JOOX 为 0%，
  该考量不再成立。
- “网易云 VIP 播不全曲”在本次实测中未复现：返回的均为完整时长的音频文件
  （按 320kbps 折算 4–5 分钟，与原曲时长一致）。

## 未包含在本版本 —— 环境音（B 站）标记为闲置

本版本**未改动**环境音模块的逻辑，仅将其标注为闲置状态。

- 现象：B 站搜索（`types=search&source=bilibili`）仍能返回 BV 号，
  但取地址（`types=url&source=bilibili`）恒为 `url: '' / br: -1 / size: 0`。
  因此环境音每轮都会解析失败——与 BGM 修复前的表现是同一类上游问题。
- 处理：代码保留（不删除），在 `ambient-audio.ts` 顶部写明当前状态与恢复判据，
  等待上游接口恢复，或改由用户手动填写备用 BV 号（`ambient_fallback_bv_ids`）绕过搜索。
- 用户侧：请在“环境音”中关闭该模块，以免每轮产生一次注定失败的请求。
- 恢复判据：B 站 `types=url` 能返回非空 `url` 且 `size > 0`。

## 其他未包含项

- 未引入音源回退（fallback）逻辑。当前为单音源单链路，
  不新增重试或跨源切换，以避免不可控的循环调用。
