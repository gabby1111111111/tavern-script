# 杠杠の配音室 v0.2.0 — 传输层迁移（豆包 + Fish 改走酒馆 /proxy）

> 发布提交：`49c0509`（前一版基线 `9c81392`）；标签：`杠杠の配音室-v0.2.0`（本地，未推送）。
> 本文记录 Step 级验收与运行时证据，供后续维护者核对；不含任何凭据。

## 一句话

四家云端引擎**零插件安装**：豆包与 Fish 的合成经酒馆自带 `/proxy` 同源转发，小米与 MiniMax 浏览器直连，
浏览器侧完全不依赖 `ganggang-tts-bridge`（桥接降级为"语音插座"阶段资产）。

## Step 0 — 前提核查（只读 + 一次授权改动）

| 项 | 教学包要求 | 8000 实测 | 处置 |
| --- | --- | --- | --- |
| `enableCorsProxy` | `true` | `false` | 改为 `true` 并重启酒馆（用户授权） |
| `basicAuthMode` | `false` | `false` | 不动 |
| `disableCsrfProtection` | 别动 | `true` | 不动（`/proxy` 另自动免 CSRF） |
| `ssl.enabled` | — | `true` | 不动（https 同源） |
| `enableUserAccounts` | `true`（教学包口径） | `false` | 不改：ST 1.18 无该自检，且 `whitelistMode` 已限局域网 |

本机特有事实（教学包未覆盖）：ST 的 `request-proxy.js` 会把 `http/https.globalAgent` 换成 ProxyAgent
（`127.0.0.1:7897`），而 `corsProxy.js` 用的 `node-fetch` 不显式传 agent，因此 `/proxy` 出口会走该代理。

浏览器内实测（页面控制台，`window.__proxyCheck`）：

```
withModel    : HTTP 200 | content-type=null | 44302 bytes | head=fffb90c4（真 MP3）| 4392ms
withoutModel : HTTP 402 | 202 bytes        | head=7b227374（JSON）
```

结论：`/proxy` 可用；`model: s2.1-pro-free` 缺头必 402；**`/proxy` 确实丢上游 `Content-Type`**（故必须有魔数兜底）。

## 已知边界与遗留

- **豆包的 CORS 硬约束**：豆包预检 `Access-Control-Allow-Headers` 只放行旧版 `X-Api-App-Key` / `X-Api-Access-Key`，
  **不放行**新版 `X-Api-Key`（2026-10-08 实抓响应头；同一 key 在 Node 里 200）。因此浏览器直连无法使用新版凭据，
  豆包必须走 `/proxy`；不要改回直连。
- 豆包与 Fish 都需要 `enableCorsProxy: true`（改完重启酒馆）；这是唯一的前置配置。
- Fish 出口偶发 `ECONNRESET`（ST 服务端日志实证），表现为 `/proxy` 500 或请求挂起；代码已映射为可读文案并设 120s 硬超时，
  **未加重试**（对齐教学包"未自动重试"口径）。
- prompt 侧遗留：AI 配音表会原样发送启用中的世界书条目（不设长度上限，2026-10-07 用户拍板）；使用者需自行避免把凭据写进世界书。
- 技术债（已在评审记录中）：新增一家引擎仍需改多处枚举；`probeBySynthesis` 与 `/proxy` 超时曾各自实现（v0.2.0 已合并为 `withTimeout`）；
  大小闸门原以错误文案判定（已改为 `TtsResponseTooLargeError`）；`runtime.ts` 的探针状态机仍无独立测试（仓库无 runtime 级测试脚手架）。
